# Правила работы над плагином «Агентство» (AGENTS.md)

## 1. Фокус и границы репозитория
- Репозиторий: `bb-plugin-agency` — официальный плагин «Агентство» для BB (команда, отделы, поручения, версии результатов, изоляция запусков).
- Вся работа в этом проекте и треде ведется **исключительно над задачами плагина «Агентство»**.
- Не подменять домен плагина внешними сущностями (BB Tasks, Workflows, внешние скрипты). Не изобретать обходные пути мимо архитектуры плагина.

## 2. Разработка сразу на main-продукте
- Любой рабочий код пишется **сразу в основную ветку `main`** реального продукта.
- Никаких временных изолированных веток-пустышек, брошенных моков или оторванного тестового кода, не входящего в продукт.
- Любые изменения вносятся в рабочие модули (`src/`, `host.ts`, `server.ts`, `app.tsx`, `skills/`, `tests/`) с сохранением целостности кодовой базы.

## 3. Работа на живом плагине в работающем BB
Плагин зарегистрирован в BB как локальный источник по прямому пути к этой папке
(`source: path:<папка плагина>`), а не как копия в каталоге BB.

Вся разработка и верификация ведутся **на живом плагине**:
1. **Контроль типов**: `npm run typecheck` (`tsc --noEmit`).
2. **Живые тесты**: `npm test` (`vitest run`). Все существующие и новые тесты должны проходить без сбоев.
3. **Сборка бандлов**: `npm run build` (`bb plugin build`). Компилирует `dist/server.js`, `dist/app.js`, `dist/host.js` и их метаданные.
4. **Перезагрузка в живом BB**: `bb plugin reload agency`.
5. **Проверка в рантайме**: обязательная проверка через реальный CLI плагина (`bb agency status --json`, `bb agency ...`) и его живой RPC/UI.

Любая задача считается завершённой только после успешного прохождения цепочки:
`typecheck` → `test` → `build` → `reload` → подтверждение в живом рантайме.

## 4. Правила интерфейса плагина (UI/UX)
Перед любым изменением UI обязательно прочитай `DESIGN.md`.
- **Единая композиция**: используй одну композицию очередей (список/канбан), подробностей (карточка задачи) и сквозной истории. Не вводи новый паттерн для отдельного экрана без согласованной архитектурной причины.
- **Штатные компоненты BB**: подключай стандартные компоненты и тему BB (`@get-bb/plugin-sdk`, `ThreadChat`, `Markdown`, `FileLink`, `ProviderModelPicker`). Собственные стили своди к минимуму и согласуй с системной темой.
- **Двухколоночная карточка**: на широкой панели (порог содержимого от 880 px) карточка задачи строится в две колонки:
  - Левая колонка: текущий этап, следующее действие, результат, описание, подзадачи, единая история.
  - Правая колонка (288 px): свойства, вложения, запуски.
  - На узких экранах правая колонка уходит под заголовок раскрывающимся блоком без дублирования интерактивных форм.
- **Единство контекста без лишних вкладок**: части, необходимые для принятия решения (результат, история, следующее действие), не прятать за вкладками.
- **Честность данных**: демонстрационный UI строго отделён от реального исполнения. Никогда не показывать фиктивные/чужие результаты, файлы или запуски как данные реальной задачи. Пустые состояния должны быть честными.
- **Сохранение черновиков**: при сбое сохранения или валидации введённый пользователем черновик (текст, выбранные роли, поля) не должен сбрасываться.

## 5. Архитектурные и доменные контракты
- **Единственный источник правды**: состояние сущностей хранится в базе данных плагина (SQLite через `better-sqlite3` с append-only миграциями), а не в разрозненных MD/YAML файлах проекта.
- **Чистый домен**: бизнес-логика переходов состояний (`src/domain/`) изолирована от I/O и проверяется Zod-схемами (`src/shared/contracts/`).
- **Изоляция и запуск (Launch Readiness)**:
  - Статус исполнения (`execution`) проверяется через `getIsolationReadiness` с `jobId`. Запуск идёт штатным `threads.spawn` (origin plugin, hidden, pluginMetadata). На проводе только публичные поля BB 0.43; идентичность запуска — база Агентства и `pluginMetadata`, навыки — в промпте снимка.
  - Запрещено объявлять запуск сотрудника или имитировать статус `running`/`done` без реального исполнения через координатор.
  - `reconcile` не является повторным запуском (respawn).
- **Вопросы владельцу (Needs Input)**:
  - Конфликты инструкций и уточнения передаются через `bb agency job report-needs-input` / `call reportNeedsInput` с сохранением `waitId`.
  - Ответ фиксируется через `answerNeedsInput`.
  - Исполнитель в скрытом треде не открывает `AskUserQuestion`: вопрос уже в Агентстве, второй канал блокирует официальный ответ.
  - В чате постановки ответ собирается штатной карточкой BB (клик по варианту и Send). `agency_ask_owner` / `bb agency job ask-owner` открывают ту же карточку, если она не появилась сама.
- **CLI и RPC**:
  - Все CLI-вызовы выполняются через allowlist-операции с обязательным флагом `--input-json` (не прямой доступ к файловой системе сервера и не сырой SQL).
  - Оптимистичный контроль параллелизма: изменения требуют `expectedRevision`. При конфликте версий перечитывать данные и разрешать конфликт.
