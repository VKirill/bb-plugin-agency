# Файловая архитектура

## Слои

`app.tsx` регистрирует страницу, `server.ts` передаёт управление composition root
`src/server/register.ts`. В точках входа нет бизнес-процесса.

- `shared/`: схемы ввода/вывода и wire-контракты. Frontend импортирует контракт
  через `import type`, не затягивает сервер и SQLite в браузер.
- `domain/`: переносимые типы и будущие правила переходов, без BB и I/O.
- `server/db/`: единственная точка открытия SQLite, последовательные миграции.
- `server/inbox/`: приём, уникальность, состояние и позже leases/outbox.
- `server/triggers/`: адаптеры CLI/RPC, позже cron, BB lifecycle и webhook.
- `server/dispatcher/`: будущий обработчик очереди и сверка запусков.
- `server/runtime/`: профиль → политика возможностей → среда → запуск BB.
  Сейчас только честный отказ: изоляция не подтверждена.
- `app/pages/`: пользовательские экраны через RPC; компоненты темы берём у BB.
- `skills/agency/`: документирует только реально существующие операции.

Внутренние зависимости идут от регистрации к сервисам, затем к домену/хранилищу.
Триггер не вызывает spawn напрямую. Домен не импортирует SDK; UI не читает БД.

## Дальнейшие файлы — создавать по мере реализации

| Каталог | Следующие модули | Обязанность |
|---|---|---|
| domain | transitions.ts, policies.ts | Проверка переходов и полномочий |
| server/db | repositories/agents.ts, jobs.ts, runs.ts, rules.ts | Версии и доменное состояние |
| server/inbox | outbox.ts, leases.ts | Сохраняемые намерения и захват работы |
| server/triggers | bb-events.ts, cron.ts, webhook.ts | Нормализация и проверка сигналов |
| server/dispatcher | engine.ts, reconcile.ts, review.ts | Запуск, восстановление, приёмка |
| server/runtime | context.ts, launcher.ts, capabilities.ts | Контекст и фактические права |
| app/pages | agents.tsx, departments.tsx, jobs.tsx, automations.tsx | Экраны настройки и работы |

`host.ts` добавляется только если изоляция потребует собственной части на host;
пустая запись bb.host сейчас не объявляется. Репозиторий не содержит пустых
десятков таблиц или функций, которые имитируют успешный запуск.

## Структура данных

План: AgentVersion, Department, ProjectBinding, Job, JobDependency, RunAttempt,
Artifact, Review, Rule, Automation, Occurrence, Inbox, Outbox, Lease.
Только Inbox уже имеет SQL-реализацию. Типы domain — проект контрактов, не CRUD API.

Права и принадлежность работника проверяются сервером. pluginMetadata годится
для поиска связанных запусков, но не для доказательства полномочий: его может
изменить агент. Перед первым запуском требуется отсечь общий административный
доступ BB, иначе сотрудник сможет поменять собственный профиль через CLI/API.

## Что считается готовым

Сборка и тесты каркаса не подтверждают изоляцию, автопилот или установку.
Страница прямо сообщает текущий этап. Отсутствующий адаптер не заменяется
промптом «не используй остальные инструменты».
