# Карта интерфейса и подключение к данным

Актуальный прототип: alpha.12, 14 сентября 2026. Маршрут
`/plugins/agency/overview`. [DESIGN.md](../DESIGN.md) задаёт единые визуальные
правила; [runtime contract](interaction-and-runtime.md) — детали взаимодействий.
Ниже текущая композиция, а не накопленная история разных alpha-экранов.

## Единое пространство

Главная — задачи по статусам, без отдельного dashboard с пустыми счётчиками.
Навигация: Работа (Задачи, Входящие), Команда (Проекты, Отделы, Сотрудники),
Управление (Автоматизации, Знания, Запуски, Настройки). Home — алиас задач.

Очереди используют компактные строки, единый поиск/фильтры, счётчик и одно главное
действие. Детали: путь и название → текущая работа/требуемое решение → материалы
и история слева; контекст, свойства и исполнитель справа. Вкладки нужны для
разных режимов настройки, а не для разрезания одной истории на четыре части.
Вопросы — исключение: несколько вопросов представлены последовательными табами.

Важное действие выделяется один раз: ответить, проверить результат, передать
в работу. Статус имеет значок и текст, не только цвет. Служебные события компактны,
сообщения имеют автора/иконку агента и вложения. Детали диагностики свёрнуты.
Имена моделей/системные IDs вторичны по размеру/цвету, но доступны для проверки.

Используем токены/компоненты BB, vendored scaffold, ProviderModelPicker и штатные
Markdown/SourceCode. Нет собственных глобальных шрифтов, палитры или копии редактора
чата. Панель адаптируется к доступному контейнеру BB, не только ширине окна браузера.
Клик по подсвеченной строке открывает её; тумблер действует отдельно и не открывает
редактор. Поиск — явно оформленное поле с label/лупой/границей.

## Задача, файлы и вопросы

Пока задачи, комментарии, вопросы и приёмка меняют пример в памяти. Само сохранение
комментария не запускает агента. В рабочей версии отдельные действия «Назначить»,
«Ответить», «Передать» имеют адресата и ожидаемый эффект перед отправкой.

Нативная вкладка файла появляется только по клику; закрывается штатно. Пока открыта,
свойства задачи справа скрыты и возвращаются после закрытия. Текст задачи остаётся
виден рядом. Документ: Чтение / Исходник / Редактор, статус сохранения и версия.
Markdown/GFM, код, таблицы, Mermaid и формулы проверяются на
[примере](examples/markdown-showcase.md), а не обещанием всех диалектов Markdown.
Дерево папок в fenced text сохраняет пробелы и прокручивается горизонтально.
YAML — свёрнутые «Свойства документа»: мелкий шрифт, ключ/значение, вложенные
объекты и списки; исходный текст не теряется. Ошибка YAML не прячет тело документа.

Прототип принимает поддерживаемые текстовые/изобразительные файлы до 5 МБ;
копия предпросмотра сохраняется на primary host. В рабочей версии — host заказа,
immutable версии/hash, серверные права, загрузка/ошибка/конфликт и восстановление
после reload. PDF/office и другие неподдержанные форматы не объявлять работающими:
штатный fallback/скачивание с ясной подписью, расширение форматов отдельно.

Вопрос выделяется над обсуждением: агент и причина ожидания, «Вопрос 1…N»,
один/несколько вариантов либо текст, Назад/Далее/Отправить. Ответы сохраняются
между табами; незаполненный обязательный вопрос отмечается. Выбор варианта сам
по себе не отправляет форму. После отправки — состояние submitting/resolved/stale,
защита повторного клика и ссылка на исходный interaction. API-ключи — защищённая
форма BB, в истории только факт предоставления. Данные секретов не являются
обычным комментарием и не дублируются в Telegram.

Передача задачи: выбрать сотрудника/модель, указать причину, увидеть что будет
передано и что произойдёт с текущим Run. Режим по умолчанию — следующая попытка;
остановка и передача требуют подтверждения stop. Параллельная работа оформляется
отдельной подзадачей. В истории остаются обе попытки и автор передачи.

## Сотрудник и инфраструктура

- Обзор: имя/роль, состояние, отделы, текущая работа; архивировать/приостановить.
- Инструкции: обязанности, ограничения, формат результата, происхождение правил.
- Исполнение: host, native CLI/model/reasoning/service-tier и permission picker,
  лимиты, политика резерва. Нет собственного статичного списка моделей.
- Возможности: выбранные skills/MCP, поиск, снять всё; собственный MCP JSON →
  валидация → preview → добавить, редактировать/выключить/удалить. Права shell,
  делегирования и файлов отдельно; secret refs вместо значений.
- История: версии и связанные Run; preview эффективного снимка до назначения.

Машина: доступна/недоступна/неизвестно и время проверки. CLI: обнаружен/отсутствует,
версия, причина ошибки, разрешён/резерв/отключён для Агентства. Отдельно показывать
непроверенную авторизацию, модель и изоляцию. Тумблер не устанавливает CLI и не
включает провайдер BB глобально. Подключения Telegram видны по capability; отсутствие
адаптера — нормальное состояние, не общая ошибка приложения.

## Автоматизация и собственные события

Источники: BB event, собственное событие, cron, webhook, ручной сигнал. В списке
понятное название и серый системный ключ; источники группируются, отсутствующие
в текущем SDK/адаптере не выглядят доступными. Registry собственных событий ещё
предстоит реализовать, нынешние 6 строк — примеры.

Webhook-редактор: источник/URL, способ auth, секрет через защищённое поле,
схема и пример JSON, условия AND, целевой проект/отдел, шаблон данных, режим,
повторы/наложения, история приёма и обработки. «Проверить» не исполняет действие;
показывает совпавшие условия, итоговый контекст и причины блокировки. Уведомление
об успешном приёме не означает успешный запуск. Cron показывает ближайшие даты,
timezone и поведение при пропуске. Любое авто-действие проходит те же права,
изоляцию и lease, что ручное.

## Проверка единства перед выпуском

На каждой странице: понятное назначение, одно первичное действие, вторичные данные
на привычном месте, keyboard/focus, подсказки ошибок у поля, длинный текст, пусто,
загрузка и отключённые действия с причиной. Проверять narrow BB pane и desktop;
не уменьшать всё подряд ради плотности. Все элементы с hover/open поведением
имеют совпадающую кликабельную область. Диагностика не заполняет историю работы
служебными простынями; пользователю видны итог и следующий шаг.
