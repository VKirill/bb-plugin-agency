# Карта поступления работы

Диспетчер обычного чата (режим «Агентство» / `pm`) не исполняет крупную работу. Сверяет фразу владельца с этой картой, ставит Job на **руководителя** отдела, запуск идёт сам.

Живые `departmentId` / `leadAgentId` бери из `bb agency workspace --json` по **точному имени** отдела. Не выдумывай отделы и не ставь работу в тестовый отдел проверки провайдеров.

Два касания владельца: утвердить предложение (новая программа) и принять готовый продукт. Кухня отделов в `needs-input` не уходит.

После стола ремесла у «Тексты и документация», «Реклама», «Дизайн», «SEO», «Маркетинг», «Контент и соцсети» и «Исследования и аналитика» живые регламенты и инструкции. У Маркетинга библиотека пустая намеренно. Остальные — кит: читай «Принимаем» в `department get`. Состав работы каждого отдела — [отделы](departments.md). Смешанный продукт — корень по этой таблице, этапы детей — [цепочки](chains.md).

Смешанный продукт — корень в отдел, который **собирает**, дети в профильные. Не отдавай всё в первый попавшийся отдел.

## Что у отдела есть для работы

### Продукт

- **Берёт:** новая программа без кода; калитка spec.
- **Инструкции:** лид оркестрирует предложение (`proposal.md`); секретарь собирает стол, стек не выбирает.
- **Пул:** `app-architect`. Код — только после принятого proposal, next-step в «Разработка».
- **Владельцу:** одно «утвердить предложение».

### Разработка

Живое имя — «Разработка» (конвейерный кит).

- **Берёт:** feature / bugfix, код по контракту.
- **Инструкции:** лид режет подзадачи с `contract` (readFirst / mayChange / checks); код пишет исполнитель; проверка другого вендора.
- **Пул:** `app-architect` плюс merge по задаче. Не ставить пакеты на машину. Нет навыка — split в «Автоматизация и агенты».
- **Не берёт:** new-program без spec.

### Дизайн

- **Берёт:** новый экран, правка/улучшение (один тип), картинка, дизайн-система, HTML-прототип.
- **Инструкции:** продуктовый → визуал → критик ui-review → пакет → приёмка → split в «Разработка». Один экран на поручение. Кухня не в needs-input.
- **Пул:** `web-design`, `design-taste`, `page-prototype`, `ui-review`, `image-studio`, `nano-banana`.
- **Сдача:** design.md + прототип без сборки + состояния. Не картинка без состояний.
- **Ремесло:** пакет после стола зафиксирован.

### Тексты и документация

- **Берёт:** документация, UI-копи, пост, вычитка, статья по ТЗ SEO, оффер лендинга, детект ИИ (проверка).
- **Инструкции:** короткий маршрут (UI, вычитка) — один исполнитель; длинный — автор → редактор другого вендора. Факты во входах. Профиль тона есть — не спрашивать.
- **Пул:** `ru-text`, `copywriter`, `ru-check`, `ru-score`, `ai-detect`, `drmax`, `telegram-rich-messages`, `markdown-pro`. Автору не выдавать ai-detect / ru-score / insights.
- **Ремесло:** пакет после стола зафиксирован.

### Реклама

- **Берёт:** медиаплан, объявления, черновик настроек, статистика **с выгрузкой**, TG Ads, Директ, Google только не в РФ по явной просьбе.
- **Инструкции:** пакет сдачи (тексты, UTM, медиаплан, import.md). Кабинет — владелец. Цифры не выдумывать.
- **Пул:** `telegram-ads`, `yandex`. `google` (`bb-user`) — merge только на не-РФ задачу.
- **Ремесло:** пакет после стола зафиксирован.

### SEO

- **Берёт:** ядро, карта раздела, ТЗ на статью, техаудит живого URL, эксперимент по URL с выгрузкой, позиции по ключам.
- **Не берёт:** статью целиком; язык ЦА (Исследования); внедрение кода (Разработка).
- **Входы:** живой сайт — URL и доступ; новый сайт — тема + принятый proposal. Переезд/склейка с трафиком — владелец.
- **Пул:** `seo-tools`, `cocoon-pilot`, `topical-graph-architect`, `gist-content-logic`, `drmax-signalforge`, `google`, `yandex`. На запуск 1–2. Новый кокон и TGA вместе не открывать. Восьмого имени нет: проверяющий без навыка из пула.
- **Ремесло:** пакет после стола зафиксирован. Без выгрузки / без proposal — возврат, не needs-input. Платный XML — баланс владельца до пачки.

### Маркетинг

- **Берёт:** позиционирование и оффер, сквозной медиаплан, **план измерения** (цели, события, UTM), разбор кампании целиком.
- **Не берёт:** объявления → Реклама; семантика/кокон → SEO; посты → Соцсети; тексты сайта → Тексты. Счётчик на сайте — Разработка `feature`. Нет фактов рынка — Исследования **до** стратегии.
- **Входы:** продукт, цена или «цены нет», сегмент, грубый бюджет/срок. Разбор — выгрузка. Нет — **возврат**, не needs-input. Юр. риск — владелец, в ветви не отдавать.
- **Пул:** пустой. Роутера стратегии в `bb-user` нет; навыки ветвей не merge. На запуск ничего не открывать. Проверяющий по артефакту.
- **Ремесло:** пакет после стола зафиксирован. Дети в ветви — после принятой стратегии. Два касания владельца: бюджет на входе и приёмка `plan.md`.

### Контент и соцсети

- **Берёт:** контент-план, **собрать публикацию**, перепаковка принятого исходника (в том числе нарезка готового видео), слушание аудитории, разбор реакций на наши посты.
- **Не берёт:** «напиши пост» как чистый текст (Тексты); съёмку с нуля (нет отдела); Telegram Ads; оффер/серию продающих — Тексты (`copywriter`).
- **Дети:** длинный текст → Тексты; картинка → Дизайн. Короткий пост без картинки пишут сами. Нет языка ЦА — Исследования, возврат. Нет обещания — Маркетинг, возврат. Публикация — владелец.
- **Пул:** `social-insights`, `ru-text`, `telegram-rich-messages`, `ru-check`, `video-to-reels`, `social-browser`. На запуск 1–2. В профилях нет. `copywriter` не merge.
- **Ремесло:** пакет после стола зафиксирован. Нет площадки / канала / обещания — возврат, не needs-input.

### Исследования и аналитика

- **Берёт:** сравнение рынка и сервисов, язык ЦА / форумы, корпус, фактчек, научные статьи, разовый мониторинг конкурентов.
- **Не берёт:** пост / статью → Тексты; оффер → Маркетинг; слушание наших соцсетей → Соцсети; кокон → SEO; внедрить в код → Разработка. Расписание мониторинга → Автоматизация после принятого `report.md`.
- **Входы:** вопрос, зачем ответ, границы. Нет — **возврат**, не needs-input. Корпус — принятой версией.
- **Пул:** `tavily`, `reddit-mapper`, `text-insights`, `alphaxiv`. На запуск 1–2. Проверяющему навык не открывать. `social-insights` / `cocoon-pilot` / `copywriter` / `copy-research` не merge.
- **Ремесло:** пакет после стола зафиксирован. Платный доступ и решение покупать — владелец. Кухню источников не тащить.

### Офис владельца

- **Берёт:** нет своего отдела; сквозной проект нескольких отделов; сводка владельцу.
- **Не берёт:** чужой пул своими руками.

### Инфраструктура и безопасность

- **Берёт:** план выкладки и отката, наблюдение, бэкапы, аудит доступов, разбор инцидента.
- **Не берёт:** функции продукта и счётчик на сайте (это Разработка). Необратимое — владелец.

### Автоматизация и агенты

- **Берёт:** навык или агент, которого нет на машине; сценарии автоматизаций Агентства.
- **Не берёт:** продукт и контент «заодно».

### Продажи и клиенты / Администрация

- **Продажи:** предложения, черновики ответов, база поддержки. Отправка — владелец.
- **Администрация:** бумаги и внутренние регламенты канцелярии. Подпись — владелец.

Не маршрут: отдел проверки провайдеров.

## Как диспетчер создаёт поручение

1. Мелкое — сделай в чате. Крупное — Job на лида из таблицы. Порядок шагов — [Поручения](job.md), «Поручить из чата».
2. Смешанное — корень собирающему отделу, не «всё в Тексты».
3. `workKind` new-program только когда продукта ещё нет.
4. Бриф: результат, входы, критерий без автора. Профиль `workProfileKey`, если есть.
5. `assignedAgentId` = lead отдела. Запуск сам.
6. Карту навыков на запуск не подбирай вручную: это лид + оценщик (до двух из пула).
