# Минимальный маршрут

Один исполнитель на связный блок → один независимый проверяющий → доставка. Разведка нужна только для конкретного неизвестного. Руководитель отвечает за полный результат и вмешательство при задержке.

- До реализации: критерии, границы файлов, нужные интерфейсы SDK, среда и доступы. Небольшой задаче достаточно брифа; адаптации нужен один общий план с остатком, владельцами и оценкой срока. Новому продукту нужна принятая спецификация; ограниченная разведка может предшествовать ей.
- План переиздаётся при изменении объёма, интерфейсов или маршрута. Дефект в согласованных границах исправляется в той же задаче без ожидания новой версии плана.
- Реализуйте законченный блок. Промежуточный тест нужен для воспроизведения ошибки, опасной границы или обязательного checkpoint. Полный gate — на готовом кандидате, обычно у проверяющего, не после каждой правки текста. Пригодный полный прогон автора на той же версии/среде не дублируется: проверяющий независимо проверяет критичный сценарий и доказательства. Индекс кода — после существенного блока исходников.
- Как только код готов и проверки кандидата прошли, передавайте точную версию существующему проверяющему. Продолжение аудита требует конкретного непокрытого критерия или воспроизведения дефекта.
- Проверяющий сверяет diff, обязательные сценарии и связанные регрессии. Принятые незатронутые доказательства сохраняются. Полный повтор требует причины: общие зависимости, среда, недостоверные доказательства или правило проекта. Мелкое оформление не создаёт новый круг.
- Команды и результаты — один раз в отчёте; комментарий содержит итог и ссылку. Сообщайте завершённый блок, блокер или передачу версии, не каждую команду. Руководитель читает изменившуюся задачу, весь граф — при смене зависимостей или маршрута. При срыве оценки он сам уточняет остаток и исправляет причину задержки.

## Необязательная оценка TypeSafe

Для спорного **законченного блока**, не для каждой правки, есть `bb agency call assessVerification --input-json '…'`. Передайте `jobId`, `phase` (`implementation`/`final`), полный `diff`, `changedPaths`, `completeDiff`, `knownFailure`, `requiredNow`. Сервер добавит полное задание и критерии; должностные инструкции в модель не уходят. Секреты не отправляйте.

| Ответ | Действие |
| --- | --- |
| `defer_to_final` | Можно не повторять промежуточное исполнение; финальная проверка остаётся |
| `targeted_now` | Проверить конкретный риск или известную ошибку сейчас; полный suite не требуется автоматически |
| `review_required` | Данных/уверенности недостаточно либо оценщик недоступен; исполнитель выбирает адресную проверку по фактам, без вопроса владельцу |
| `final_checks` | Выполнить обязательную итоговую проверку точной версии |

Это рекомендация по времени проверки, не доказательство корректности. `advisory=true`, `finalChecksRequired=true` всегда. Известная ошибка, обязательный checkpoint и чувствительные пути не могут получить отсрочку от модели. Порог 0.9 — консервативный порог маршрутизации, не «90% тестов пройдут»; его качество на наших задачах ещё нужно измерять. Отказ API не блокирует работу и не разрешает пропуск. Журнал содержит решение, ответы, длительность и hash/длину входа, не сырой код.

## Приёмка и восстановление

Контракт сохраняет `readFirst`, `interfaces`, `mayChange`, `mustNotTouch`, `checks`. Обязательные проверки проекта не удаляются и не ослабляются. Непроверенный сценарий не PASS; ноль Gap в каталоге не доказательство исполнения. Автор не принимает собственную реализацию.

Сдача: результат и report.md с версией, критериями, фактическими проверками и остатком → `artifact publish` → `job submit` с точной версией и hash. План/промежуточный отчёт не являются сдачей. Корень завершает необходимые доставку/живую приёмку и рабочие подзадачи; сохраняет один итоговый отчёт.

Второй похожий отказ → руководитель читает `job diagnose`, устанавливает причину (код/среда/входы/контракт/конвейер). Третий провал → решение руководителя и одно штатное продолжение после проверенного ремонта. Не сбрасывайте историю/лимит копиями, не меняйте модель вместо диагностики, не перезапускайте здоровую попытку. Ремонт конвейера требует адресной регрессии и независимой проверки. Урок сохраняется после результата и не задерживает доставку. Новые полномочия и изменение заказа — владельцу; уже разрешённое выполняется самостоятельно.

Новые комплекты используют этот процесс. Существующий отдел меняется через `department save` с `expectedRevision`; активным сотрудникам изменение передаётся в тот же тред. Модели сохраняют предпочтения владельца. Автопроверка не создаёт вторую станцию, если назначенная проверка уже существует.
