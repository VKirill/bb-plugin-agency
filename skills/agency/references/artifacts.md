# Документы и приёмка в Агентстве

## Источник истины

Artifact/ArtifactVersion плагина — реестр результата. YAML/JSON agency-artifacts описывает содержимое документа и не заменяет этот реестр.

- Plugin artifact ID и общий `artifact_id: art_...` не считать одним форматом: если ID несовместимы, сохранить общий ID документа и ссылку на plugin artifact/job в `extensions.agency` по согласованной схеме. Не переписывать выданный сервером ID.
- Job плагина не является записью штатного BB Tasks. Для общего task_ref использовать `system: external`, `id: <реальный Job.id>`; не присваивать system=bb-task по одному ключу AG-42.
- ArtifactVersion.author имеет kind=user/run/system; поле owner документа имеет другой смысл и другой набор значений. Не преобразовывать их неявно.
- Для RPC использовать точную camelCase-схему плагина; не добавлять `_meta`, YAML-поля или произвольный status в закрытый payload.

## Сохранение

1. Определить Job, его binding.hostId/canonicalRoot и доступный интерфейс артефактов. Имя папки из каталога — предложение, не замена root плагина.
2. Подготовить файл по инструкции задачи; при совместимом формате применить agency-artifacts. Raw и закрытые схемы сохранять; метаданные — sidecar, если требуются.
3. Передать через CLI: `artifact create` / `artifact publish --input-json` с bytesBase64 (или `--bytes-file` + `--source server-fs` на диске плагина). Не читай чужой host по произвольному canonicalRoot. open печатает метаданные без bytes.
4. Полученную версию проверить: artifactId, jobId, version, hostId, relativePath, mime, size, hash. Version и фактический hash возвращает/проверяет сервис; не подменять их значениями шаблона.
5. Перечитать версию/openArtifact через доступный интерфейс. Запись файла вручную ещё не означает регистрацию в плагине.

`publishArtifactVersion` здесь означает регистрацию версии в плагине, не публикацию сайта/поста во внешний канал.

## Ревью

Принятие относится к artifactId + jobId + текущая version + hash. Устаревшую версию сервер должен отклонить. Новое содержимое требует новой неизменяемой версии; прежняя приёмка не переносится. approved в YAML не является вызовом acceptArtifactVersion и не завершает Job.

Ревьюер возвращает критерий → evidence/место → решение или исправление. Переход в done подтверждается сервером после приёмки текущей версии и выполнения reviewPolicy. Если интерфейс приёмки недоступен, передать заключение с версией, не объявлять задачу принятой.
