# Трассировка задач

`bb agency trace` (`listTrace`) — доступный владельцу журнал ключевых шагов конвейера в SQLite Агентства. Он дополняет историю задачи и тредов. Не содержит полного текста задания, ответа модели, команд инструмента, секрета или сообщения исключения.

```sh
bb agency trace --input-json '{"jobId":"AG-177","limit":50}' --json
bb agency trace --input-json '{"jobId":"AG-177","minRepeats":3}' --json
bb agency trace --input-json '{"outcome":"failed","since":"2026-09-22T00:00:00Z"}' --json
bb agency trace --input-json '{"minDurationMs":10000,"limit":100}' --json
```

`jobId` принимает id или ключ. По умолчанию включает подзадачи; `descendants:false` оставляет одну задачу. Для выгрузки следующей страницы передайте `nextBeforeId` как `beforeId`, сохраняя фильтры. Порядок — от новых событий к старым, максимум 200 записей за вызов. Для файлов используйте каталог `tmp/` текущего чата.

| Поля | Что устанавливают |
| --- | --- |
| jobId / rootJobId / relatedJobId | Работа, её корень и связанная проверка/родитель |
| step / outcome / reason | Действие, исход и машинный код причины |
| revision / state / artifactHash | Наблюдаемое состояние и конкретная версия результата |
| requestId | Начало и завершение одного вызова; `started` без завершения требует проверки треда/перезапуска |
| attemptId / launchId / threadId | Связь с реальным исполнением; отсутствующее значение остаётся null |
| firstAt / lastAt / repeats | Период и число одинаковых наблюдений |
| durationMs | Длительность вызова; для повторяемого ожидания — максимальная наблюдавшаяся |
| summary | До 30 наиболее частых сочетаний шага/исхода/причины по фильтру, независимо от страницы |

Трассируются команды работы с задачами/версиями/входами и запуском, оценщики, очередь, допуск приёмки, вердикт и таймаут проверки, стоп круга, доставка руководителю и сохранение знаний. Бизнес-состояния по-прежнему определяются доменными таблицами, не этим журналом.

Одинаковые последовательные наблюдения одного шага и состояния объединяются. После смены причины или ревизии начинается новая запись. Поля счётчика и последнего наблюдения могут обновиться после выгрузки страницы; это снимок диагностики, не неизменяемый поток аудита. Хранение: 30 дней с момента последнего наблюдения, до 50 000 строк; очистка происходит во время записи. Старые события задним числом не восстанавливаются.

`health.writeFailures` и `lastFailureAt` показывают сбои записи с последней загрузки плагина; предупреждение попадает в `bb plugin logs agency`. Ошибка диагностики не должна менять результат бизнес-операции. Журнал помогает находить причины, но сам не исправляет произвольные ошибки.

## Отказ запуска и руководитель

Недостающая спецификация, конфликт разрешённых файлов и другие предусмотренные устранимые отказы создают одно сохраняемое поручение руководителю. Оно доходит через существующий механизм parent wake в точный текущий тред руководителя. В поручении есть причина и действия; исходная задача остаётся в очереди. Повтор того же условия не создаёт ещё одно поручение. Подтверждённый запуск закрывает инцидент.

`lead.issue` показывает создание/снятие блокировки; `lead.delivery` — попытку доставки и её результат. Состояние `queued` доставки означает очередь сообщения, а не прочтение руководителем. Если сообщение не доставлено за 10 минут, владелец получает сигнал о недоступном руководителе. Успешная доставка не доказывает, что руководитель исправил проблему: это видно по `condition_cleared`, запуску и проверке результата.

Руководитель сохраняет подтверждённые решения в знаниях своего отдела; журнал фиксирует сохранение/принятие, но не превращает каждый отказ в новое правило автоматически.
