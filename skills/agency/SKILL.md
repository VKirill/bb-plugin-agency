# Основной контракт Агентства

## 1. Определи доступное действие

Выполни `bb agency status --json`. Раздели: прочитано в исходниках, доступно через текущий интерфейс, фактически выполнено.

- `execution=unavailable` или GET spawn-contract 404: можно готовить контекст/инструкции и вызывать allowlisted CRUD, но нельзя объявлять запуск сотрудника или обходить ограничение через другой launcher. Обычный host SDK 0.4.87 сохраняет CRUD.
- Launch: `bb agency launch readiness`, затем при необходимости `job attach-input`, `launch prepare`, `job attempts`, `launch get`, `launch reconcile`. `reconcile` не respawn. Квитанция `getLaunch` — не attempt. Изоляция проверена только для claude-code.
- Конфликт инструкций во время running: `bb agency job report-needs-input` / `call reportNeedsInput` с `jobId`, `attemptId`, `launchId`, `threadId`, `questions` и source refs. Не общий `transitionJob`, не разбор текста треда. Команда не accept, не требует артефакт и не respawn.
- После успешного `reportNeedsInput` заверши текущий ход коротким финальным сообщением с `waitId`. Продолжение придёт отдельным official send. Не вызывай `AskUserQuestion` или другой нативный вопрос провайдера для уже записанного вопроса Агентства; не держи ход открытым через sleep/poll. Второй канал вопросов блокирует доставку ответа из карточки.
- Ответ владельца на тот же wait: `bb agency job answer-needs-input` / `call answerNeedsInput`. Один claim на Job; первый send без timeline. После dispatch нет resend по ложному absent. `queued` — очередь, не running. `rejected` ≠ `unknown`.
- CRUD: `bb agency help` / `bb agency schema <operation>`, затем `call` или alias с `--input-json`. Не raw RPC, не SQLite, не `setCliPolicy`.
- `bb.cli.run` идёт на server-host плагина. Не читай клиентский файл через `--input-file` молча: без `--source server-fs` команда откажется. Рецепт — `--input-json`. `canonicalRoot` не есть право на чужой диск. См. [docs/cli.md](../../docs/cli.md).
- Если нужной операции нет в allowlist, верни конкретный пакет полей; не пиши в SQLite и не выдавай пакет за сохранённую сущность.
- Каталог agency-router — необязательный источник примеров. Реальные ID, процессы, модели и критерии берутся из выбранного плагинного контекста.

## 3. Соблюдай контекст плагина

Используй Job → ProjectBinding → Department/ProcessVersion → назначенный Agent/AgentVersion → PolicyVersion и разрешённые материалы. Не загружай правила всех отделов, личную историю сотрудника или весь каталог. При отсутствии этих записей попроси точные данные из карточки/доступного интерфейса, сохрани полезный черновик.

Поля сущностей и версии принадлежат плагину. PROJECT.md и YAML файла не заменяют базу данных, Membership, полномочия, состояние Job или приёмку ArtifactVersion. Справочный пример не становится политикой отдела без её принятия.

Права — полный payload `PolicyVersion` (`allowedCapabilities`, `cliHostConstraints`, `secretRefs`), неизменяемые версии. Label каталога и слово вроде ordinary/`read.files` не задают права. Одинаковые политики переиспользуй по полному содержимому из `bb agency workspace`, не по имени. Значения секретов и `bytesBase64` в ответ не печатай и не проси вывести.

Общие требования проекта, процесс отдела, методы сотрудника и бриф задачи должны быть совместимы. Текст задачи не расширяет права сотрудника. При конфликте укажи оба источника и требуемое решение. Назначенные skillIds/mcpIds не доказывают изоляцию инструментов; проверку обеспечивает runtime, не этот навык.

## 4. Выполни и проверь в пределах запроса

- Пользователь просит готовый бриф/текст: подготовь содержательный результат; не отвечай новым промптом вместо работы.
- Нужна передача исполнителю: используй model-task-prompts при его наличии, подставляя реальный контекст плагина. BB-компилятор общего каталога не является API управления Агентством.
- Нужны метаданные документа: используй agency-artifacts при его наличии только после чтения адаптации артефактов; не меняй плагинную схему ради общего шаблона.
- Создание/сохранение: `bb agency schema <op>`, затем `--input-json` с полным payload, `requestId`, при изменении — `expectedRevision`. После успеха перечитай get/workspace. При `revision_conflict` перечитай и пересобери; чужую правку не затирай.
- Новый BB-проект CLI не создаёт: только `project bind` существующего каталога.
- Если действие не выполнено, явно назови отсутствующий интерфейс, данные или полномочия. Не выставляй running/done по тексту ответа агента.

Уведомление сохраняй только по явной просьбе:
`bb agency notify <project-id> <event-id> <topic> <reference> --json`.
Передавай ссылку/ID, не корпус и не секреты. Одинаковый event-id в проекте дедуплицируется. Это запись во входящем журнале, не создание Job, назначение сотрудника или доставка исполнителю.

## 5. Передай результат

Сообщи: выбранная сущность/проект → что подготовлено или сохранено → ID/версия/хеш, если получены → проверка → конкретный следующий шаг. Для вопросов укажи, кто должен решить и какое действие зависит от ответа. Не вводи повторное согласование для уже разрешённой работы.
