# Агентство

Агентство — организация из агентов внутри BB. Владелец ставит цель и получает готовый продукт корня, не штампы станций. Отделы делают работу на конвейере: внутренние приёмки и ОТК не зовут заказчика. Каждое действие остаётся в базе плагина и видно в интерфейсе.

## Модель

```text
Отделы агентства — общие, принимают задачи из любого подключённого проекта
├── Регламент отдела (ProcessVersion): что принимаем и не принимаем, процесс, класс результата, проверка
├── Руководитель (Agent + membership lead)
├── Исполнители и проверяющие (Agent + membership executor | reviewer), у каждого должность и инструкция (AgentVersion)
└── Помощники (membership assistant + «кому помогает»): подзадачи на дешёвой модели, не ведут главную задачу и не раздают работу
Проект (ProjectBinding) — папка BB-проекта на одной машине: там запускаются сотрудники
Поручение (Job): проект + отдел + исполнитель + бриф + критерий приёмки
├── Подзадачи (Job с parentJobId), у главной задачи прогресс по ним
└── Попытка запуска → скрытый тред на машине проекта → версия результата (ArtifactVersion) → приёмка
```

| Термин | Что это на самом деле |
| --- | --- |
| Проект | Папка BB-проекта на одной машине с политикой прав. Там запускаются сотрудники и лежат файлы задач. Один BB-проект может быть подключён на нескольких машинах. Одна привязка на проект; раздел — область знаний внутри привязки (`Job.sectionId`), не вторая привязка |
| Отдел | Команда с руководителем, регламентом и составом. По умолчанию общий для всех проектов, можно ограничить выбранными |
| Регламент | Текст и критерий результата отдела. Правка создаёт новую версию |
| Сотрудник | Агент с должностью, инструкцией, провайдером, моделью, навыками и политикой. Не тред и не модель |
| Тип роли | Руководитель / исполнитель / проверяющий / помощник — в составе отдела. Определяет, что делает система; должность — свободный текст |
| Поручение | Конкретная работа с брифом и критерием приёмки. Главная задача — у которой есть подзадачи |
| Запуск | Попытка исполнения поручения в отдельном скрытом треде |
| Приёмка | Решение по конкретной версии файла (`artifactId + version + hash`), а не слово «готово» |

## Десять правил

1. **Правда — в базе плагина.** Читай и меняй через `bb agency`. Не SQLite, не Markdown-доска, не фраза «готово» в чате.
2. **Работа принадлежит отделу, куда её поставили.** Нужна работа другого отдела — подзадача в том отделе, а не выполнение чужой работы.
3. **Руководитель отвечает за конечный результат.** Сам выбирает маршрут, читает и анализирует доступные факты, организует обследование, план, исполнение и проверку. Production-реализацию делегирует; техническая неизвестность не означает вопрос владельцу.
4. **Исполнитель берёт только свой пул работ.** Не свой или без обязательных входов — возврат по правилам, а не «попробую».
5. **Исполнитель ≠ проверяющий.** Проверку назначай участнику с типом `reviewer`; свою работу он проверить не сможет — сервер отклонит (`self_review`). Дефект — подзадача доработки и повторная независимая проверка.
6. **Результат — опубликованная версия и явная сдача `job submit`.** Обычный `job comment` — только обсуждение. Публикация ≠ приёмка. Автора версии ставит сервер; свою работу принять нельзя.
7. **Вопрос владельцу — `report-needs-input` один раз, затем закончи ход.** Вопросы открывают штатную карточку в чате заказчика. В скрытом рабочем треде не AskUserQuestion и не `agency_ask_owner`. В чате заказчика — штатная карточка выбора (`agency_ask_owner`), не опрос A/B/C текстом.
8. **Каждое изменение — с `requestId` (новый UUID) и, где требуется, `expectedRevision`.** При `revision_conflict` перечитай и пересобери, чужую правку не затирай.
9. **Запуск объявляй только по квитанции `launch prepare`.** `reconcile` не перезапускает.
10. **Не выдумывай ID, модели, навыки и права.** Бери из `bb agency workspace --json`, `bb agency catalog capabilities --json` и `bb provider models <providerId>`. Модели нет в этом BB — `bb agency agent repair-models`, а не тихая замена руками.

## Три неудачных прохода

Уже при втором похожем отказе руководитель читает `bb agency job diagnose --input-json '{"jobId":"AG-235","limit":100}' --json`: фактические вердикты, trace, попытки и видимые сообщения. Старые попытки выбираются через `attemptId`, страницы сообщений через `beforeSeq`. Подробности — [диагностика](references/diagnostics.md). Не заменяйте анализ сменой модели; сохраняйте принятые незатронутые критерии и отделяйте новые пожелания от дефектов.

После третьего неудачного прохода обычные повторы блокируются. Отмена и новый запуск не обнуляют историю; три ошибки запуска до появления треда тоже требуют разбора. Инцидент получает руководитель отдела. Если активного родительского треда нет, Агентство создаёт руководителю задачу на восстановление.

Руководитель читает попытки, замечания проверки и историю, исправляет причину в пределах выданных полномочий. Можно корректировать инструкции, входы, конфигурацию доступа, плагины и собственный конвейер. Изменение кода — отдельная задача с регрессионной проверкой и независимым ревью. Проверенный урок сохраняется в знаниях отдела. Дополнительные полномочия, новые секреты и изменение требований запрашиваются у владельца.

После проверки исправления руководитель сразу вызывает `bb agency job recover --input-json` с `requestId`, `jobId`, актуальным `expectedRevision`, `comment` и `recoveryDecision: {cause, correction, verification}`. В `verification` указываются конкретные файлы, версии, хеши и результаты проверки. Решение сохраняется и разрешает одно продолжение исходной задачи: для результата на проверке — возврат в существующий тред, для остановленного запуска — штатная очередь. Это не сброс бюджета и не разрешение отключать проверки. Исполнитель не может разрешить себе повтор; руководитель не может сам разрешить повтор своей собственной неудачной задачи.

Если независимая проверка уже приняла точную текущую версию, но старый отказ предварительного оценщика или сбой создания автопроверки мешает закрытию, не возвращай автора на новую сдачу. Руководитель/владелец вызывает `bb agency artifact accept --input-json` с обычными полями версии и `reviewResolution: {reviewJobId, reason}`. Проверка должна быть завершена отдельным проверяющим, иметь опубликованный отчёт и явный положительный вердикт; точная версия должна быть прикреплена до публикации отчёта. Активную автопроверку так заменять нельзя. Решение сохраняется в истории запросов и трассировке `review.resolve`; другие условия приёмки остаются обязательными.

## Команды

Полный пример любого payload: `bb agency schema <operation>`. Все изменения — `--input-json '{…}'`, `requestId` — новый UUID (`uuidgen | tr A-Z a-z`).

| Задача | Команда |
| --- | --- |
| Всё о проектах, отделах, сотрудниках, задачах | `bb agency workspace --json` |
| Навыки и MCP для сотрудников | `bb agency catalog capabilities --json` |
| Сотрудник: создать / прочитать / сохранить профиль | `bb agency agent create\|get\|save` |
| Модели сотрудников: сверить с этим BB и перевести на доступные | `bb agency agent models\|repair-models` |
| Отдел: создать / прочитать / сохранить; состав | `bb agency department create\|get\|save`, `department membership add\|remove` |
| Подключить, отключить, вернуть, удалить проект | `bb agency project bind\|archive\|restore\|delete` |
| Доступ отдела: все проекты или выбранные | `bb agency department availability`, `project link-department\|unlink-department` |
| Поручение: создать / прочитать / изменить / сменить статус | `bb agency job create\|get\|update\|transition` |
| Восстановить исходную задачу после разбора руководителем | `bb agency job recover` |
| Сравнить прошлые вердикты, попытки и сообщения | `bb agency job diagnose` |
| Вернуть версию на доработку с замечаниями | `bb agency job return` |
| Порядок работы: задача ждёт другую; следующий шаг другому отделу после готовности | `bb agency job depend\|undepend\|next-step` |
| Актуальная цель, дети, решения, кандидаты в уроки; решение руководителя; сдача | `bb agency job state\|decide\|submit` |
| Комментарий в историю, оценка на входе, входные версии, попытки | `bb agency job comment\|attach-input\|attempts` |
| Расход токенов и оценка стоимости задачи с подзадачами | `bb agency job usage` |
| Вопрос владельцу и ответ | `bb agency job report-needs-input\|answer-needs-input` |
| Ответ чата постановки на зависшую задачу | `bb agency job stale-answer` |
| Готовность, запуск, сверка, остановка; очередь запуска | `bb agency launch readiness\|prepare\|get\|reconcile\|cancel\|queue\|unqueue` |
| Результат: создать, опубликовать версию, открыть, принять | `bb agency artifact create\|publish\|open\|versions\|accept` |
| Правила проекта: прочитать и сохранить `.bb/AGENTS.md` | `bb agency project rules\|rules-save` |
| Режим обычных чатов проекта или этого треда | `bb agency session get\|save` |
| Правила работы: пороги, лимиты, модели по умолчанию; бюджеты и расход | `bb agency rules get\|save\|budgets` |
| Общие правила Агентства (верхний слой промпта) и шаблоны форм | `bb agency rules agency-get\|agency-save`, `bb agency templates list\|save` |
| Знания: список (фильтр `scopeKind` / `scopeId` / `parentBindingId`, в том числе раздел), одна запись целиком, предложить материал, решение по записи своего отдела | `bb agency knowledge list\|get\|save\|status` |
| Идеи и туду владельца: список (фильтр проекта/раздела), одна запись, сохранить обсуждение, сменить статус, открыть тред | `bb agency idea list\|get\|save\|status\|thread` |
| Профили работ проекта: голос, стиль, эталоны | `bb agency profile list\|save\|delete` |
| Паспорт проекта: прочитать, собрать заново, поправить, вернуть редакцию | `bb agency passport show\|build\|save\|rollback` |
| Оценщик: настройки, журнал, проверка связи и живой прогон точек | `bb agency decisions get\|save\|test\|log\|probe` |
| Библиотека навыков отдела и журнал выдач | `bb agency skills pool\|pool-save\|grants` |
| Цели главных задач; поиск и архив задач; показатели сотрудника | `bb agency goal list\|link`, `bb agency job search\|archive`, `bb agency agent metrics` |

## Отчёт владельцу

Что сделано → ключи AG-N, ID и версии → чем проверено → следующий шаг и кто решает. Если действие не выполнено, назови, чего не хватило: команды, данных или прав.
