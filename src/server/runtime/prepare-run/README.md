# prepare-run

Независимая подготовка ContextSnapshot + `reservePreparedRun`. Compiler, run-store
и coordinator не меняются. Register / RPC / UI / live spawn нет. Рабочую
path-install Agency не reload. Установленный `node_modules` / package не
перенастраивать.

## Own paths

| Путь | Роль |
| --- | --- |
| `src/server/runtime/prepare-run/` | этот модуль (owns) |
| `tests/prepare-run.test.ts` | SQLite compiler + store + coordinator |

Не owns: `context-snapshot/compile.ts`, `run-store/**`, `launch/**` internals,
`server/register.ts`, установленный package.

## Public integration input

Только `{ requestId, jobId, expectedRevision }`.

Не public: `applicable`, `trustedSources`, catalog roles, attestation,
readiness/handshake. Их держит `VerifiedPrepareConfig` на сервере.

`trustedSources` **выводит** сервер: `sourceId=binding` = live
`ProjectBinding.hostId` + `canonicalRoot`. Parent — только явный
server-verified source, не client root. Pin
`pinBindingRuleSource` отклоняет mismatch до read/wiring. Registry policy
не изобреталась.

## Catalog roles

Явные `catalogRoles.core` / `helpers[]`: `id` + `source` на server config.
`list({ projectId, environmentId, hostId })`.

## Skill package hash

Inventory = `SKILL.md` ∪ `listFiles` (safe relative), minus generated bytecode
(`__pycache__/**`, `*.pyc`, `*.pyo`). Hash только этих файлов.
Markdown-ссылки `](relpath)` должны быть в inventory. Backticks / `<filename>.meta.json`
и прочие примеры — не references и не placeholder в пакете.

## Job inputs

Public `prepareLaunch` remains `{ requestId, jobId, expectedRevision }`.
Published versions are attached by a separate `attachJobInput` command
(`targetJobId`, `sourceJobId`, `artifactId`, `version`, `hash`, optional handoff).
Caller does not send `hostId` / `canonicalRoot`. Prepare reads persisted pins only;
published ≠ accepted; `acceptedArtifacts` stays empty until an acceptance row matches the pin.
`parentJobId` is not a grant.

## Public SDK caller names

`experimental_callerLaunchId` / `experimental_callerAttemptId` /
`experimental_callerJobId`. Internal `launchContract.launchId` не меняется.
Isolated adapter — отдельная копия Agency, не этот path-install package.
